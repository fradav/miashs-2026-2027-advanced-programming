2  Prérequis

Pour ce module, il vous faut deux outils de base — un éditeur de code et un gestionnaire d’environnements Python — plus, pour le parcours A, l’accès à un modèle de langage. Toutes les options proposées ici sont gratuites ; les limites effectives de chaque offre sont indiquées (vérifiées le 25/08/2026).

2.1 Éditeur : Zed

Zed est l’éditeur utilisé en TD. Il est gratuit, rapide, et intègre un assistant de code (Agent) qui peut être branché sur n’importe quelle API compatible OpenAI — dont les offres gratuites décrites plus bas.

  • Installation : https://zed.dev/ (macOS, Linux, Windows).
  • Aucune configuration nécessaire pour écrire du code ; seul le panneau Agent doit être relié à un modèle (voir L’outillage du parcours A).
  • (Optionnel) un compte Zed gratuit permet l’édition collaborative dans des channels (voir Édition collaborative).

2.2 Gestion des environnements Python avec uv

uv est l’outil de gestion d’environnements Python recommandé. Il installe l’environnement et les paquets dans le répertoire courant.

Voir la documentation d’installation pour votre plateforme. Ensuite :

uv init          # crée un environnement dans le répertoire courant
uv add package   # ajoute un paquet (remplacer package par le nom)

Exécuter un script avec une dépendance ponctuelle :

uv run --with dependance script.py

2.3 L’outillage du parcours A : un tuteur IA

Le parcours A nécessite l’accès à un modèle de langage (LLM). Trois options, toutes gratuites, selon votre matériel et vos goûts — le sondage de démarrage distribué en séance nous aidera à calibrer ce choix :

2.3.1 Option 1 — API OpenRouter (recommandée)

OpenRouter est un agrégateur : une clé API donne accès à des dizaines de modèles (Llama, Qwen, Gemma, DeepSeek, gpt-oss, Nemotron…) via une seule API compatible OpenAI.

  1. Créez un compte sur https://openrouter.ai/ (email ou GitHub, aucune carte bancaire).
  2. Générez une clé API (page Keys de votre compte).
  3. Dans Zed, ajoutez un fournisseur OpenAI-compatible :
    • URL : https://openrouter.ai/api/v1
    • Clé : la clé OpenRouter
    • Modèle : ouvrez la collection Free Models et copiez l’identifiant d’un modèle dont l’ID se termine par :free (au 25/08/2026 : 17 modèles — ex. z-ai/glm-5.2:free, cohere/north-mini-code:free, google/gemma-4-31b-it:free, nvidia/nemotron-3-ultra-550b-a55b:free). Le catalogue change souvent : si un modèle disparaît, la page Free Models liste le remplaçant. Vous pouvez configurer plusieurs modèles et basculer de l’un à l’autre dans le panneau Agent.

Limites effectives (25/08/2026) — le plafond porte sur le nombre de requêtes, pas sur les tokens :

Limite Compte gratuit Après un achat de ≥ 10 $ de crédits
Coût par token (modèles :free) 0 $ 0 $
Requêtes par minute 20 20
Requêtes par jour 50 1 000
  • Le quota quotidien remonte à 1 000/jour dès que le compte a acheté au moins 10 $ de crédits une fois (crédits valables à vie) — l’augmentation reste acquise même si le solde retombe à zéro. Une seule « recharge » de 10 $ sur un compte de classe suffit donc.
  • Les modèles gratuits sont servis à priorité basse : attente possible aux heures de pointe, et le catalogue des modèles :free change régulièrement (certains disparaissent, d’autres apparaissent) — d’où l’intérêt de configurer plusieurs modèles.
  • Les requêtes échouées (429 = limite atteinte) comptent dans le quota du jour.
  • En tokens, OpenRouter n’impose pas de quota global sur les modèles gratuits : la taille d’une requête est bornée par la fenêtre de contexte du modèle (au 25/08/2026 : de 64k à 1M tokens, ex. z-ai/glm-5.2:free en 256k, nvidia/nemotron-3-ultra-550b-a55b:free en 1M) et le débit (tokens/min) est fixé par chaque fournisseur — souvent réduit aux heures de pointe. Seuls les compteurs de requêtes (20/min, 50/jour) font foi au niveau d’OpenRouter.
  • Vérifiez la politique de données de chaque fournisseur : certains endpoints gratuits peuvent s’entraîner sur vos échanges. Évitez d’y envoyer des données sensibles.

Si chaque étudiant crée son propre compte OpenRouter (2 minutes), chacun dispose de ses 50 requêtes/jour — c’est l’option la plus simple et la plus sûre pour une classe.

2.3.2 Option 2 — API Mistral (clé gratuite)

Mistral « La Plateforme » offre un plan gratuit Experiment : accès à tous les modèles (Mistral Small, Medium, Large, Codestral, Magistral…), sans carte bancaire, mais avec une vérification par téléphone.

  1. Créez un compte sur https://console.mistral.ai/home et récupérez une clé API. Un numéro de téléphone valide est nécessaire — prévenez l’enseignant si c’est un problème.
  2. Dans Zed, ajoutez un fournisseur OpenAI-compatible :
    • URL : https://api.mistral.ai/v1
    • Clé : la clé Mistral
    • Modèle : mistral-small-latest (raisonnement activé avec reasoning_effort: "high", voir le dépannage plus bas) ou mistral-medium-3-5 (plus puissant, même mécanisme).

Limites effectives (plan Experiment) — chiffres approximatifs et non publiés (exacts dans la console, section Limits) : environ 1 milliard de tokens/mois, ~500 000 tokens/min par modèle et ~1 requête/s par clé API (2 req/min selon certaines sources). Les quotas détaillés varient par groupe de modèles (ex. magistral : 20 000 tokens/min, 10 req/min). Ce plan sert à expérimenter, pas à produire.

Données : les requêtes du plan gratuit peuvent servir à l’entraînement des modèles Mistral (rétention ~30 jours, cf. leur politique de confidentialité) — n’y envoyez pas de code ou d’échange sensible.

Pour les modèles à raisonnement, voir le dépannage ci-dessous.

2.3.3 Option 3 — Modèle local (si votre machine le permet)

Si vous avez au moins ~16 Go de RAM (ou un GPU dédié avec ~6 Go de VRAM) et ~8 Go d’espace disque libre, vous pouvez faire tourner un modèle local type Qwen 3.5-4B (≈5,5 Go quantifié) avec llama.cpp ou LM Studio. Un modèle local fonctionne hors ligne et sans compte ; Zed s’y connecte comme fournisseur OpenAI-compatible (http://localhost:11434/v1). Le sondage de démarrage (distribué en séance) sert précisément à savoir qui peut en faire tourner un.

Si votre machine est modeste : ne vous inquiétez pas. L’option 1 ou 2 (API gratuite) suffit pour suivre le parcours A. Le parcours B, lui, ne nécessite aucun outil d’IA.

2.4 Dépannage : le raisonnement (« thinking ») de Mistral ne s’affiche pas

Trois causes fréquentes :

  1. Vous utilisez un modèle qui ne raisonne pas, ou une ancienne appellation. Le raisonnement est aujourd’hui ajustable et se déclenche par le paramètre reasoning_effort :
    • Modèles concernés : mistral-small-latest et mistral-medium-3-5 — ils ne réfléchissent que si on envoie reasoning_effort: "high" (défaut = "none" : pas de thinking).
    • Les dénominations magistral-*-latest (raisonnement « natif », toujours actif) sont dépréciées chez Mistral (25/08/2026) : magistral-small-latest résout désormais vers mistral-small-latest, à raisonnement ajustable. Préférez mistral-small-latest avec reasoning_effort: "high".
    • Les autres modèles (Large, Codestral…) n’ont pas de mode raisonnement : leur envoyer reasoning_effort provoque une erreur HTTP 422.
  2. Le paramètre est mal placé. reasoning_effort est un champ racine du corps de la requête Chat Completions (pas dans extra_body, pas dans un message).
  3. Le format de réponse change. Avec reasoning_effort: "high", message.content devient une liste de chunks (ThinkChunk – la trace, puis TextChunk – la réponse) au lieu d’une chaîne de caractères. Un code qui lit content comme une chaîne « n’affiche rien » ou plante. Deux précisions utiles :
    • En streaming, delta.content change de forme : liste ThinkChunk pendant la réflexion, puis liste mixte (fin de ThinkChunk + premier TextChunk) à la transition, puis chaîne simple pour la réponse finale. Un code qui attend toujours le même type « n’affiche rien » sans crasher.
    • Soyez tolérant au découpage : selon les modèles, la réponse peut contenir des ThinkChunk vides intercalés dans les TextChunk (bogue rapporté sur magistral-medium-latest). Ne gardez que le texte des TextChunk et ignorez le reste.
    • En multi-tour, renvoyez dans l’historique le message assistant complet (avec sa trace) : retirer le ThinkChunk des tours précédents dégrade nettement la qualité.

Exemple minimal qui marche (SDK Python mistralai) :

from mistralai import Mistral
from mistralai.models import TextChunk

client = Mistral(api_key="VOTRE_CLE")
resp = client.chat.complete(
    model="mistral-small-latest",
    messages=[{"role": "user", "content": "Explique le concept de verrou (lock)."}],
    reasoning_effort="high",
)
content = resp.choices[0].message.content
if isinstance(content, str):
    print(content)  # reasoning_effort="none" : chaîne simple
else:
    for chunk in content:
        if isinstance(chunk, TextChunk):
            print(chunk.text, end="")  # on ignore les ThinkChunk (trace)

Même chose en curl (la clé dans une variable d’environnement MISTRAL_API_KEY) :

curl https://api.mistral.ai/v1/chat/completions \
  -H "Authorization: Bearer $MISTRAL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"mistral-small-latest","reasoning_effort":"high","messages":[{"role":"user","content":"Explique le concept de verrou."}]}'

Dans Zed : déclarez Mistral comme fournisseur OpenAI-compatible (https://api.mistral.ai/v1) et, pour le modèle, réglez reasoning_effort sur "high" dans sa configuration (available_models dans les réglages de l’Agent). C’est ce réglage qui active le thinking et demande à Zed d’afficher la trace dans le panneau. Sur des versions plus anciennes de Zed, reasoning_effort pouvait ne pas être transmis pour les fournisseurs OpenAI-compatible (bug corrigé depuis) — mettez Zed à jour si le thinking ne s’affiche pas. Notez que Mistral renvoie la trace dans message.content (chunks), pas comme champ dédié : un outil qui attend une chaîne simple peut afficher « rien ». Pour voir la trace en toutes circonstances, utilisez un script (comme ci-dessus) ou Mistral Le Chat.

2.5 Édition collaborative

Zed permet l’édition collaborative : un participant ouvre un channel (public ou privé) et les autres le rejoignent avec le lien. Les séances pourront utiliser cette fonctionnalité ou le salon Discord du module (le canal exact sera indiqué en TD).

2.6 Faire tourner multiprocessing/asyncio en Jupyter

Sous macOS, multiprocessing exige la méthode spawn dans les notebooks Jupyter — un correctif exige des réglages propres au noyau. Le plus robuste reste d’exécuter vos scripts avec uv run plutôt que dans une cellule de notebook ; le détail est repris en TD si besoin.
